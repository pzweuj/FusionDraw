# FusionDraw

[中文 README](README.md) · English

FusionDraw is a browser-first fusion-gene diagram engine. Annotation lookup and rendering are deliberately separate: GTF data is compiled into static annotation packs, while the renderer consumes only a resolved `FusionPlotSpec`.

The project produces research illustrations and report graphics. It is not intended for clinical diagnosis.

## Project links

- GitHub repository: [pzweuj/FusionDraw](https://github.com/pzweuj/FusionDraw)
- Planned deployment: [https://fusiondraw.biotools.space](https://fusiondraw.biotools.space)

## SVG render API

### URLs

The planned production API is:

```text
POST https://fusiondraw.biotools.space/api/render-svg
```

For local development, use:

```text
POST http://127.0.0.1:5173/api/render-svg
```

If Vite selects another port, use the URL printed in the terminal. The API accepts a complete `FusionPlotSpec` JSON body and returns `image/svg+xml`.

### Minimal request

This is the smallest coordinate-free request. It is suitable for an abstract schematic; a biological fusion diagram should provide the actual retained exon segments:

```json
{
  "specVersion": "0.1",
  "coordinateSystem": "1-based-inclusive",
  "locale": "en",
  "fivePrime": {
    "gene": { "symbol": "A" },
    "transcript": { "exons": [{ "label": "1" }] }
  },
  "threePrime": {
    "gene": { "symbol": "B" },
    "transcript": { "exons": [{ "label": "1" }] }
  },
  "fusion": {
    "name": "A::B",
    "fivePrimeExons": [{ "label": "1" }],
    "threePrimeExons": [{ "label": "1" }]
  },
  "chromosomeView": { "show": false }
}
```

### Request fields

- Top-level fields must include `specVersion: "0.1"`, `coordinateSystem: "1-based-inclusive"`, `locale` (`en` or `zh-CN`), `fivePrime`, `threePrime`, and `fusion`.
- Each partner needs a gene symbol and a `transcript` with an `exons` array.
- `fusion.fivePrimeExons` and `fusion.threePrimeExons` are the retained fusion segments. When the labels represent a real exon range, use one object per exon instead of a single range string such as `1-13`.
- For a chromosome/genomic view, provide `assembly`, chromosome, a 1-based inclusive breakpoint, and strand for each partner. If a `resolution` is included, its transcript ID and exon/intron fields must be complete and consistent with the partner.

### Example

```powershell
curl.exe -X POST https://fusiondraw.biotools.space/api/render-svg `
  -H "Content-Type: application/json" `
  --data-binary "@fusiondraw.json" `
  -o fusiondraw.svg
```

For local testing, replace the production host with the active Vite URL.

Response contract:

- A valid PlotSpec returns `200` with `image/svg+xml`.
- An invalid PlotSpec returns `400` with a JSON body containing `error`.
- Browser CORS preflight uses `OPTIONS` and returns `204`.
- Other methods return `405`; allowed methods are `POST, OPTIONS`.

## Agent skill

The project-level [FusionDraw SVG skill](skills/fusiondraw-svg/SKILL.md) instructs an Agent to generate SVG from user-provided drawing information.

The Agent should:

- keep the 5′ partner (`fivePrime`) and 3′ partner (`threePrime`) order explicit;
- collect both gene symbols and the retained fusion exon segments for a schematic request;
- ask focused follow-up questions before calling the API when required information is missing, and never invent a transcript, exon range, or genomic coordinate from a fusion name alone;
- offer an explicitly labelled placeholder schematic when the user lacks biological data;
- collect assembly, chromosome, breakpoint, strand, and the needed transcript/resolution data for a real genomic view;
- prefer `https://fusiondraw.biotools.space`, unless the user provides another base URL; use the local Vite URL only when the production endpoint is unavailable and local development is in scope;
- return or save a successful SVG response as requested, without calling it PNG/JPG or interpreting it as a clinical diagnosis.

The skill can also be invoked explicitly:

```text
$fusiondraw-svg
```

## Annotation and editing capabilities

- The demo includes small hg38 and hg19 fixtures, so the complete Automatic → Advanced → SVG workflow works without a backend.
- Production packs are generated by `annotation-builder/build_annotation.py` and should be versioned through manifest checksums.
- Compiler-generated packs record per-shard SHA-256 values. `StaticAnnotationProvider` uses the manifest checksum as the Cache API namespace and verifies a shard before using it, so a stale or corrupted cached response cannot silently enter a plot.
- The exported `applyPlotExonEdit` helper keeps biological coordinate edits independent from visual label/width/visibility changes. Clearing either coordinate explicitly removes the coordinate pair instead of falling back to the original exon.
- Automatic resolution is terminal on annotation errors: the resolver returns `errors` without `data`, so a caller can explicitly continue with a manual PlotSpec.
- Providers may expose pinned release metadata through `getMetadata`; the resolver copies its source, annotation version, and pack checksum into `PlotSpec.provenance`.
- Editable fusion exons are stored independently from the source transcript: biological edits live under `exon.biological`, while label/width/visibility edits live under `exon.visual`.
- Breakpoint coordinates are 1-based inclusive. When a breakpoint splits an exon, the 5′ segment keeps the breakpoint base and the 3′ segment starts at the following transcript-direction base, avoiding double coverage.

FusionDraw is intended for research and report illustration, not clinical diagnosis.
